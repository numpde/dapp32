Shared CAM UI backlog
=====================

Action pairs put the primary action first and the quiet secondary or cancel
action second, in source, keyboard and visual order, including when wrapped.
The repository check flags adjacent literal quiet-then-prominent JSX buttons;
browser checks cover rendered order and keyboard behavior. Computed styles,
conditional markup and unrelated actions still require review.

Native dialogs use the shared dismissible-dialog owner: Escape and a pointer
press and release outside dismiss them. Outside dismissal follows the same
discard behavior as Cancel. The owner uses native light dismissal where
available and a pointer-position fallback elsewhere; browser checks exercise
both paths and keep inside clicks and drags from dismissing the dialog.

1. Shared URI input and display components

   Requested: 2026-10-29. Status: in progress.
   Owner: shared CAM UI authoring/rendering, with adoption across Bike,
   Escrow, Pay-to-Play and other apps wherever a value is a document location.

   Preserve the exact input, provide syntax feedback and explicit open/load
   actions, and reuse existing resource validators and download permissions.
   Supported schemes must match the consumer: HTTPS, IPFS and embedded data
   URIs are not interchangeable everywhere. Do not fetch automatically or
   imply that valid syntax proves reachability, safety or matching content.

   Coordinate URI input with recorded URI/digest presentation: opening a
   document and verifying its bytes are separate actions. This capability
   belongs to shared UI, not an app-specific plugin.

   Fields accepting prose as well as links, such as Bike missing reports,
   resolutions and public profiles, remain text fields.

   Related evidence: note 031, issue 28 (Escrow recorded documents).
   Design workshop and cross-app inventory: note 041.
   The first slice adds shared URI elements, embedded text/JSON and decoded
   document hashing for Escrow terms, submissions and disputes. NFT
   detail views now use the shared URI display for the supplied metadata URI,
   with explicit document inspection separate from NFT preview loading. Bike
   supplies the token URI returned by its component read; the mutable base and
   submitted-suffix issue in note 042 remains unresolved for transaction review.

3. Field hints and useful field-local validation

   Status: in progress. Owner: shared CAM UI input/action boundary, then
   authored app forms. Support concise examples and associate failures with
   their fields; broader document inputs remain to review.

   First-party TextFields now declare exact hex lengths or UTF-8 byte bounds
   where applicable. Bike serials and lifecycle reports preserve all text but
   require a nonempty value; Escrow references use the contract-projected
   limit, and IDs and Pay-to-Play invoice hashes and signatures have exact
   byte-shape feedback. Bike profile text is deliberately unrestricted and
   empty clears it. The authoring check rejects undeclared constraints but
   cannot prove a declaration matches a contract or a signature is authentic.

6. Open question: share prepared forms through links and QR codes

   Status: open design question; implementation not selected.
   Owner: shared viewer form sharing/navigation, with app-specific use cases.
   Example: prepare Bike registration with serial number, intended NFT owner
   and metadata, then give someone a QR/link that opens the populated form.
   Existing links restore a route and its inputs, but not the editable draft.

   Decide which draft values are shareable, how recipients inspect/edit them,
   and how URL/QR size limits affect embedded metadata. Also decide how a
   shared draft behaves if the app's fields or contract bindings have changed.
   Sharing must not carry wallet credentials or transaction approval, select
   a signing wallet, or automatically submit a transaction. Form values in a
   shared link are disclosed to anyone who receives it.

   The historical PoC QR renderer is a reference, not a migration decision.
   A QR represents the same prepared-form link; URL/draft construction belongs
   to its existing shared owner rather than the QR display component.

7. Align text in shared single-line controls

   Status: complete. User screenshot reported 2026-10-29 after height unification.
   Owner: shared viewer control CSS and native/composite control rendering.
   Native select text layout used a different line height from text inputs;
   the compact address preview also used a different font from its editor.
   Selects now share the text-field line height and leading inset, with a
   shared decorative chevron while retaining native select behavior. Address
   previews and editing use the same monospace font and inset.

   Verification: native select keyboard behavior, address editing, focus and
   popup placement pass the shared browser suite. Text insets and preview
   alignment were checked at 1280/761/320 with normal and doubled text size.
   Browser evidence is Chromium; other browser engines were not exercised.

8. Reset copy feedback and align identifier copy controls

   Requested: 2026-11-03. Status: complete.
   Owner: shared browser clipboard feedback and identifier/copy-control CSS.
   User screenshot shows persistent success ticks beside the viewing account,
   signing wallet and CAM contract, with imperfect vertical alignment between
   identifier text and its adjacent copy icon/tick.

   Successful copy feedback now returns to the idle copy icon after two
   seconds for both identifiers and JSON, through the shared clipboard owner.
   Repeated copies restart the timeout; changing the value or unmounting
   retires old feedback and timers. Clipboard failures remain actionable
   rather than clearing on the success-feedback timeout. Browser checks cover
   repeated copying, expiry, persistent failure and stale copy completion.
   JSON uses the same copy-icon control at the top-right of each block.
   Copy and success icons now share one SVG size rather than mixing an icon
   with a font-rendered tick. Identifier text uses an explicit block line
   box, including inside links, so link baselines cannot offset the copy icon.

   Verification: copy and success SVGs share the identifier text's vertical
   centre, including linked identifiers, at 1280/761/320 and normal/doubled
   text size. Existing full-value selection, keyboard copying and focus checks
   pass. This is separate from the input/select alignment in item 7.
