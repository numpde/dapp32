Local releases with public CAM publication

2026-10-23 · Implementation and local checks

Deploy Bike NFT, Escrow and Pay-to-Play through the normal release workflow onto the persistent local chain, then render each deployed workflow in an existing browser tab. Publish each CAM bundle through GitHub over HTTPS and store its public root URI with an all-zero root hash. The viewer must visibly identify that root as unverified; declared resource integrity checks still apply.

Original obstacle, now resolved

Before this change, local setup coupled the fixture chain, funded test deployer and internal http://release-cam:8080/<app>/main.json publication. The shared network alone exposed neither service to a host browser. Setup now accepts public publication independently of chain selection; network/local/viewer/up attaches a browser to an existing release without deploying another instance.

Keep make <app>/release/setup, release/deploy and release/verify as the sole release path for all three apps. Preserve clean-source admission, protected configuration, plan validation, the reviewed approval image and per-transaction operator approval. Do not add a second demo deployer or grant the signer internet access. The existing isolated automatic rehearsals retain their private CAM server, temporary chains and cleanup behavior.

End state

Setup records the local chain choice separately from the public manifest URI and zero hash. Normal deployment saves its ordinary artifact; normal verification checks the resulting contracts and ownership on that same chain. Any required authority handoffs remain explicit operations.

Provide the browser a deliberately bounded local RPC route to the persistent chain. The browser itself fetches the GitHub-hosted root and relative ABI/UI resources using CORS; no signer fetch or private CAM mirror supplies those bytes. Use the deployment artifact for launch coordinates: chain ID and CAM root address, together with the browser-reachable RPC endpoint. These coordinates locate the contract; the viewer must still discover the manifest URI, hash and bindings from that contract. Reuse the existing browser tab without replacing its browser session or redeploying contracts.

Acceptance evidence

Focused tests must reject mismatched local chain/deployer inputs while accepting public CAM publication independently, preserve zero/nonzero hash semantics, and assert the browser RPC boundary's rendered container posture. Existing approval and isolated rehearsal checks must continue to pass.

For each app, complete normal setup, approved deployment and verification on the persistent chain. Record artifact identity and contract reads proving the public URI and zero hash. In the existing tab, observe successful cross-origin root/resource fetches, contract-driven discovery, the unverified-root indication and a rendered workflow. Keep these live observations distinct from automated qualification.
