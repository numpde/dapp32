Deploy Pay-to-Play

Instance settings, contract authority and acceptance checks for the Pay-to-Play example app.

Example app guide · Shared setup, deployment and verification

This page defines the app-specific inputs and checks. Use the shared guide for source snapshots, protected configuration, approval, records and cleanup. Example addresses and paths below are placeholders; your saved configuration selects the actual instance.

Deploy a release

Use make pay-to-play/release/deploy to deploy one CAM host and one native-asset PayToPlay contract to a selected chain. The script binds the payment contract in the CAM host. It creates only reserved channel 0; service channels are created later by the payment admin.

Use the shared walkthrough to collect every setting once and save one complete configuration, including the RPC URL, deployer key and deployment confirmation:

make pay-to-play/release/setup CONFIG=/absolute/private/pay-to-play.json
make pay-to-play/release/deploy CONFIG=/absolute/private/pay-to-play.json

For a local test deployment, first run make network/local/up, then choose local in setup. Run the same deploy and verify commands afterward; the network stays running until make network/local/down. Use make network/local/info to show connection details, and make network/local/status to see container state and health, including stopped services. Local setup supplies the funded public ba test key, local RPC/CAM URLs and chain 31338.

The local manifest URI is http://release-cam:8080/pay-to-play/main.json (HTTP). It is reachable only inside the Docker network. No ports are published to your host, so your browser cannot open it. This flow supports container-based deployment and verification; browser or wallet testing needs separate network exposure. See the local network flow.

When setup asks for an output directory, choose a new off-repo path such as /tmp/local-release, with an existing parent. Deployment creates it and saves plans, transaction records and contract addresses there. Keep it: verification reads its artifact/deployment.json. The CONFIG file holds the deployment inputs and is separate from these output records.

The CONFIG file must be new and outside the checkout, with an existing parent and no symlink path components. Setup creates it with mode 0600; loading requires that mode and your ownership. It pins the source commit and has no dependency on the RPC catalog or other credential files. Review all inputs before saving. The shared release walkthrough also serves Escrow and Bike NFT. The manual environment interface is described below.

For a public deployment, publish the checked-out cam/ bundle at an immutable HTTPS location, or pin it in content-addressed storage. Keep its relative ABI, UI and protocol paths available. Validate the local files against the intended publication URI first:

make pay-to-play/cam/publication/preflight CAM_URI=https://example.org/releases/COMMIT/pay-to-play/main.json

This validates local bytes; it does not upload files or test the public server. Check that the published bytes match, and that the server permits browser reads with CORS when using the web viewer. The current web viewer requires HTTP(S) resource transport; an IPFS publication needs an explicit supported gateway path.

Prepare the funded deployer's key and HTTPS RPC URL in separate, owner-only files outside the checkout. Select a clean committed source revision and install its locked dependencies with make dapps/deps/install and make js/deps/install. Replace the example addresses, paths and publication URI below:

RPC_URL_FILE=/absolute/private/rpc-url \
DEPLOYER_PRIVATE_KEY_FILE=/absolute/private/deployer-key \
PAY_TO_PLAY_RELEASE_EXPECTED_CHAIN_ID=84532 \
PAY_TO_PLAY_RELEASE_CAM_URI=https://example.org/releases/COMMIT/pay-to-play/main.json \
PAY_TO_PLAY_RELEASE_INTENDED_CAM_ROOT_OWNER=0x1111111111111111111111111111111111111111 \
PAY_TO_PLAY_RELEASE_INTENDED_PAYMENT_ADMIN=0x2222222222222222222222222222222222222222 \
PAY_TO_PLAY_RELEASE_NULL_CLAIM_PERIOD=86400 \
PAY_TO_PLAY_RELEASE_OUTPUT_DIR=/absolute/new/pay-to-play-release \
CONFIRM_PAY_TO_PLAY_RELEASE_DEPLOY=YES \
make pay-to-play/release/deploy

The chain number above selects Base Sepolia, a public testnet with its own gas tokens. Use the chain you intend to deploy to. Both owner addresses must be nonzero; they may differ or be the same account. The CAM owner can replace the manifest and contract binding. The payment admin can create service channels and change their payees. Neither authority comes from the wallet currently viewing CAM.

PAY_TO_PLAY_RELEASE_NULL_CLAIM_PERIOD is the fixed withdrawal wait for reserved channel 0, in seconds from 0 through 2,592,000 (30 days). Zero means there is no wait on that channel. Service channels get their own fixed waits when the admin creates them.

The command saves plan/release-plan.json, the Forge broadcast under broadcast/, and artifact/deployment.json. If an intended owner differs from the deployer, deployment starts a two-step ownership transfer on that contract. Using their own transaction client, the CAM owner calls acceptOwnership() on the saved camRoot address, and the payment admin calls it on payToPlay. These are separate transactions. They are unnecessary for an authority that already equals the deployer.

Until each transfer is accepted, the deployer remains that contract's owner.

To change the payment admin later, PayToPlay's current owner calls transferOwnership(newOwner) on payToPlay; the nominee then calls acceptOwnership() there. There is no built-in waiting period, and the current owner retains authority until acceptance. This changes payment administration independently of CAM ownership.

After the transfers are accepted, run:

make pay-to-play/release/verify CONFIG=/absolute/private/pay-to-play.json

For a deployment made with individual environment inputs, use:

RPC_URL_FILE=/absolute/private/rpc-url \
PAY_TO_PLAY_DEPLOYMENT_ARTIFACT_FILE=/absolute/new/pay-to-play-release/artifact/deployment.json \
make pay-to-play/release/verify

Verification requires the same clean source commit. It submits no transactions. It checks creation receipts and deployer identity, the CAM digest and binding, both accepted ownership transfers, runtime hashes, reserved-channel settings and the EIP-712 signing domain. PayToPlay embeds its own address in runtime code, so source verification checks its actual creation-transaction input against the compiled creation code and constructor arguments. Creating and funding ordinary channels afterward does not invalidate these checks.

The release artifact is pay-to-play.deployment.v1; its transaction hashes and creation-input hash are evidence for these checks, not a replacement for them. Run make pay-to-play/release/check for offline tool tests. Shared snapshot, credential, output and failure handling are documented in the release ceremony. Explorer source publication is a separate step.
