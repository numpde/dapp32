Choose a deployment task

Hosting the viewer, hosting workflow files and deploying contracts are separate operations. Read what runs where before choosing which one to change.

Provide or open a viewer

Deploy the viewer on a server to provide a website. Open a saved publication locally to inspect existing contracts. Neither task requires another business-contract deployment.

Deploy a new app

Follow the new-instance procedure: choose authorities, approve deployment, host the prepared files, then approve CAM publication. Start with your app's settings: Bike NFT, Escrow or Pay-to-Play.

Change an existing app

For compatible screens and navigation, use the CAM-only update. Preparation does not upload files; host them before publication approval.

For a new read-only Solidity helper, use projection replacement. Business-contract replacement needs a separate migration decision, not a UI refresh.

Recover or verify

Recover an interrupted release before starting another creation. Its cancellation section explains owned cleanup and uncertain outcomes.

Publish or recheck original compiler sources with Sourcify. External verification failure does not undo a deployment or require a replacement contract.

Practice without public funds

Keep a local release chain between commands, or run an isolated automatic rehearsal. These differ from the simple browser demo.

Test a reviewed approval image with explicit fixture-only rejection or success checks.
