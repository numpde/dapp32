What runs where?

An app author describes a workflow in JSON. A contract publishes where to find it. A generic viewer reads that description and displays the app; a compatible agent can interpret it without drawing a screen. Business contracts, not the description, enforce the rules.

Four parts, not one deployment

PartLocationResponsibility
ViewerJavaScript in the user's browser; static assets on a web serverDiscover, render, prepare reads/writes, and ask a wallet to authorize.
CAM bundleHosted filesmain.json describes routes; UI, ABI and protocol resources provide their definitions.
CAM host, often CamRootBlockchainAdvertise the manifest URI/hash and resolve named contract addresses.
Business contractsBlockchainHold application state and enforce balances, permissions and lifecycle rules.

Browser → RPC → CAM host → manifest/resources → screen.
Approved action → wallet → RPC → business contract → receipt → next read.

RPC gives access to a selected chain. The wallet authorizes transactions. Neither is supplied merely by hosting the viewer. The browser also needs permission and network access to fetch the app's resources.

Follow one deposit

  1. You choose the network and CAM host. The viewer reads its publication through RPC and loads the declared files.
  2. You open a balance. A read returns the owner's state and the viewing account's available actions.
  3. You enter 100 wei. The UI stores a local draft; no money has moved.
  4. You review the action. The viewer prepares the destination, arguments and native value and can simulate them.
  5. Your wallet authorizes submission. The business contract checks the real sender, value and current state.
  6. A successful receipt establishes execution. The next read shows the new balance.

A simulation can become stale. A transaction hash alone is not success. Viewing an account is not authority to spend from it.

“UI” can mean three different things

The browser viewer is software you host. The CAM UI description is the JSON defining screens and controls. A Solidity projection contract is an optional read-only helper that assembles screen data. Replacing one does not automatically replace the others.

What hashes do—and do not—tell you

The current format uses SHA-256 over exact manifest and resource bytes. Matching hashes can connect files to a selected host's publication; they do not establish that the publisher, workflow, RPC or deployed code is trustworthy. Address bindings can change separately.

The browser viewer can continue after an integrity warning. Treat that as a warning, not a successful authentication. Before authorizing, check the actual chain, destination, arguments and value. The protocol trust-boundary reference gives the precise rules.
