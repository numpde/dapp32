Try Pay-to-Play with a local wallet

Launch the app, create a test channel and deposit 100 wei. This uses public fixture accounts on a disposable local blockchain, not your real wallet.

Run on
Your workstation, from the source checkout.
Requires
Docker with Compose, Make, and Chrome or Chromium. Use a separate browser profile without wallet extensions.
Changes
Local containers, temporary blockchain state and a dedicated browser profile. No public-chain transaction.
Success
A successful deposit receipt and a 100-wei balance in the selected test position.

1. Start the app — terminal A

Replace your-local-context below and in terminal C with the same local Docker context. Use the same project name in every command.

make dapps/deps/install DOCKER_CONTEXT=your-local-context
make js/deps/install DOCKER_CONTEXT=your-local-context
make pay-to-play/local/demo/gui/up \
  DOCKER_CONTEXT=your-local-context COMPOSE_PROJECT_NAME=cam-demo

Leave this command running. It starts Anvil on chain 31337, deploys the app and prints a complete viewer URL, normally on http://127.0.0.1:5175. A fresh chain has only reserve channel 0. Do not infer a service channel ID from a previous run.

2. Open an isolated test browser — terminal B

google-chrome \
  --remote-debugging-address=127.0.0.1 \
  --remote-debugging-port=9222 \
  --user-data-dir="$HOME/.cache/cam-local-test-browser" \
  --no-first-run

Use chromium instead of google-chrome when that is your installed executable. Keep this profile exclusively for local fixtures. The debugging endpoint controls that browser: keep it on loopback and do not add real accounts, secrets or wallet extensions.

In this browser, open the entire URL printed by terminal A, including its query parameters. Opening only the port loses the fixture coordinates.

3. Attach the test wallet — terminal C

Run from the same source checkout:

make viewer/local/fixture-wallet/attach \
  DOCKER_CONTEXT=your-local-context COMPOSE_PROJECT_NAME=cam-demo \
  FIXTURE_WALLET_APP=pay-to-play \
  CDP_ORIGIN=http://127.0.0.1:9222

Choose the matching app tab if prompted. The attachment reads the saved fixture deployment and verifies the tab, chain, host, manifest and payment contract. It refuses a tab that already has a wallet provider. It does not start another browser or chain.

Keep terminal C running. In the app, connect the fixture wallet. Its selector starts on the customer; changing roles changes the acting account. Wait for the app to refresh after each change. Sending asks for confirmation in terminal C.

4. Create a channel as the fixture admin

Select admin in the fixture wallet, then connect or let the app update. Open channel creation. For this local experiment, use the fixture admin's displayed address as both payee and collector and choose a 60-second claim period.

Review the call, send it, and approve it in terminal C. Read the new channel ID from the successful receipt's ChannelCreated event—not from an observed channel count.

5. Deposit as the fixture customer

Select customer and wait for the app to update. Open a balance using that customer's displayed address and the channel ID from the receipt. Choose Deposit, enter 100 in the wei/base-unit input, review and send.

Approve in terminal C. Check that the receipt succeeded and that the resulting balance is 100 wei. The six task destinations should remain visible, with Balance now an overview rather than a page full of editors. Funding alone does not authorize voucher collection; the voucher-key and signing workflow is a separate next task.

6. Stop what you started

Stop terminal C first; it removes its injected wallet and selector without closing the tab. Then stop terminal A and let cleanup finish. To explicitly remove the matching demo resources:

make pay-to-play/local/demo/gui/down \
  DOCKER_CONTEXT=your-local-context COMPOSE_PROJECT_NAME=cam-demo

Close the dedicated browser. Its profile remains on disk; the fixture's blockchain state is disposable. Closing a tab alone does not stop the demo. Never import these public fixture keys into a wallet used with real funds.

When a step fails

No matching tab: check that you opened terminal A's complete URL in the CDP browser and used the same context/project in terminal C. Existing wallet rejected: use the isolated profile, not a browser with a real provider. Action unavailable: check the active role, selected owner/channel and latest state. Port busy: stop the old owned fixture/browser; do not kill unrelated services.

Source procedure: Pay-to-Play local demo at 04a18763. For a persistent server website, use Deploy the viewer, not this fixture.
