Local test wallet

Use public test accounts in an existing local app tab without a wallet extension. Choose an account in the selector; the app receives a wallet-account change and rechecks its actions. The contract still enforces permissions.

Attach to an existing tab

make viewer/local/fixture-wallet/attach \
  FIXTURE_WALLET_APP=escrow \
  COMPOSE_PROJECT_NAME=dapps \
  CDP_ORIGIN=http://127.0.0.1:9222

Use pay-to-play, escrow or bike-nft and the same COMPOSE_PROJECT_NAME used to start that demo. The default project name is dapps. The command reads the demo's existing deployment volume without changing it; missing records fail without creating a replacement volume.

The saved deployment supplies the CAM host, manifest URI and granted contract addresses. Attachment finds the existing browser tab for that origin, host and local chain 31337. A sole match is selected automatically; several matches prompt for a choice in your terminal. Open the URL printed by the demo first. No browser tab IDs, viewer URLs or contract pins need to be copied.

Attachment verifies and pins the current manifest hash from the contract, checks the downloaded manifest and ABI hashes, and requires the original contract bindings. It rechecks those pins before signing and broadcasting. It refuses a tab that already has a wallet. It does not start or stop the browser, app or chain.

After editing a demo, run its local/demo/gui/refresh Make target with the same project and GUI settings. This rebuilds the viewer, validates the CAM files and updates their on-chain hash with the public fixture account when needed. Contracts and balances stay in place; original deployment records are retained. Reload the page, then stop and rerun wallet attachment if its manifest pin changed.

Use the selector

Choose Connect wallet in the app after attachment. The selector chooses the active account; Reconnect wallet asks the app to connect again using that account. A transaction’s Send with wallet button asks for browser confirmation. Confirming signs and submits immediately using the selected public test account. Voucher signatures must still be created in a separate signer.

Keep this foreground process running. Reloading the page resets the selector to the app’s configured initial account and requires connecting again. Ctrl-C removes the test wallet and selector and leaves the tab open. It rejects pending requests and prevents new signing or submission phases. A transaction already submitted cannot be undone. If the process is forcibly killed, reload the tab before attaching again so a leftover page wallet does not remain without its signing process.

Configure an app test

The app module under js/apps/cam-web/test supplies its named accounts and allowed transactions. Each account supplies an address and private key; the tool checks that they match before accessing the browser. Names do not confer permissions. For example:

accounts: {
  customer: { address: '0x...', privateKey: '0x...' },
  settlementAgent: { address: '0x...', privateKey: '0x...' }
}

Use only publicly known test private keys for disposable local chains. Private keys stay in the test process; the page receives account names, addresses and transaction responses. A pending request keeps the account it started with even if the selector changes. The tool does not unlock Anvil accounts.

The app configuration grants functions separately for each destination and limits native value, gas and call size. These limits do not grant permissions that the contract denies. Bike selects seller, mechanic or buyer; manager writes and the three-argument NFT transfer are granted only at their respective pinned targets. Historical or other NFT collections need separate authorization. Accounts must already have local test coins for gas; attachment does not fund them. It adds no wallet feature to the production viewer or CAM protocol.
