Overview Bike NFT Escrow Examples

Author a contract-defined workflow

Use a host contract to publish a manifest, explicit routes to describe reads and writes, and a small UI catalog to collect inputs and display contract state. Start from the checked-in Bike NFT or escrow bundle.

Give each part one responsibility

  1. The business contract enforces permissions, amounts, lifecycle transitions, and deadlines. It must remain safe when callers bypass the UI.
  2. The host, currently CamRoot, publishes camURI and camHash and resolves contract namespace names to chain-specific addresses. Its owner controls that publication and those bindings.
  3. cam/main.json declares the CAM version, entry route, namespaces, resources, and routes. Escrow uses "cam": "1.1.0"; Bike NFT uses "cam": "1.0.0". The current reader supports both.
  4. ABI resources describe contract calls. Contract namespaces point directly to ./abi/ContractName.json; the manifest pins those bytes with SHA-256 integrity.
  5. cam/ui.json declares named UI nodes; current UI version is 1.0.0. Its bytes are also pinned in the manifest.
  6. An optional read projection returns semantic views and permitted action IDs. It aggregates business state without forwarding writes or becoming an authorization subject.

The host's manifest hash is Keccak-256 of the exact root manifest bytes. ABI/UI resource integrity uses SHA-256. Escrow document digests also use SHA-256, but are application commitments with a different purpose. Do not interchange these hashes.

Follow the actual escrow read route

This complete route excerpt comes from escrow's manifest. It reads the projection for the currently viewed account and hands the first output to the UI's app node. It belongs inside routes, not in a standalone manifest.

{
  "kind": "read",
  "inputs": [],
  "call": {
    "namespace": "contracts.CamEscrowUI",
    "function": "viewCreateAgreement",
    "args": { "client": "$account.address" }
  },
  "then": {
    "namespace": "ui",
    "function": "app",
    "args": { "view": "$outputs.0" }
  }
}

The contract namespace declares its ABI URI and integrity in namespaces; the host supplies its deployed address. Route argument names must match the ABI. $inputs refers to declared route inputs, $account.address to the account being viewed, and $outputs.0 to the first call output. These are protocol expressions, not JavaScript.

Keep calldata and payment together

CAM 1.1 permits native transaction value. Escrow's creation route uses the same nested amount for calldata and value. After a confirmed write, the declared continuation looks up the new agreement by client and reference.

{
  "kind": "write",
  "inputs": ["params"],
  "value": "$inputs.params.amount",
  "call": {
    "namespace": "contracts.CamEscrow",
    "function": "createAgreement",
    "args": { "params": "$inputs.params" }
  },
  "then": {
    "namespace": "routes",
    "function": "lookupAgreement",
    "args": {
      "client": "$account.address",
      "agreementRef": "$inputs.params.agreementRef"
    }
  }
}

Read routes continue to UI nodes. Write routes continue to another route. A prepared write is calldata and value for simulation and wallet review; it is not authorization or proof of execution. The business contract must reject invalid calls even if a UI advertises them.

Compose a declarative UI

Named nodes declare requires: ["view"] when they receive a view argument. Include calls UI nodes, Button calls routes, and fields bind local state.key values that expressions can read through $state. Escrow's app node selects a named screen using $view.viewId.

Current UI elements and their purpose
Elements Use
Screen, Fragment A titled screen or a group of children.
Text, Address, Status, Nft Display text, addresses, values, and NFT references. Address displays an address; it is not an input field.
TextField Collect text, including manually entered document URIs and digests.
AmountField Collect an exact base-unit amount with native/display-unit conversion, using a declared unit.
NonNegativeIntegerField Collect whole nonnegative decimal integers with optional min/max bounds; escrow sets a minimum of 1 for durations.
Include, Button Compose named UI nodes or dispatch declared routes.

This complete anonymous field excerpt is from escrow's UI; place it among a node's children:

{
  "element": "AmountField",
  "props": {
    "label": "Escrow amount",
    "unit": {
      "assetId": "native", "baseLabel": "wei",
      "displayLabel": "Native asset", "decimals": 18
    }
  },
  "state": { "key": "amount", "defaultValue": "" }
}

Use enabledWhen against contract-provided action IDs to disable unavailable actions. This improves the rendered workflow but does not replace onchain enforcement. There is no supported automatic document-upload or document-hashing component; escrow uses TextField and external SHA-256 calculation.

Validate the bundle before publishing

Keep Solidity under dapps/<name>/src/ and tests under test/. Deliberately create cam/abi/ before ABI export. This guide explains the existing bundles; it is not a one-command scaffold for a new dapp. A new dapp also needs explicit ABI outputs admitted in compose/forge-abi.yml and a manifest output admitted in compose/cam.yml. Follow their existing mount patterns and the rendered-config checks under tests/checks; do not grant writes over the repository root.

make deps
make package-deps
make abi
make cam-conformance-check
make checks

make abi exports manifest-declared ABIs and refreshes local integrity pins. For UI-only resource edits, make cam-integrity refreshes pins without ABI export. Inspect generated changes and run the relevant contract, package, and local workflow checks. Conformance validates deterministic publication joins and resource integrity; it does not prove live authorization, RPC reliability, wallet behavior, or security.

For the existing escrow app, make escrow-release-deploy plans and deploys a release only with its required explicit confirmation, chain, publication, owner, secret-file, and output settings; make escrow-release-verify verifies that recorded release. Use the complete commands and prerequisite publication steps in escrow's release guide and the shared release ceremony. They own root-hash calculation and address binding; replace no required settings with guesses. New dapps need their own deliberate deployment wiring. Viewers validate contract-returned manifests, resources, URLs, and actions as untrusted input. A matching hash proves byte identity, not an audit or an honest publisher.

Open and inspect a workflow

The browser startup query accepts chainId, host, account, and rpcUrl, all required. The local Make target prints the complete URL. Read-route navigation uses the fragment, for example #route=agreement&agreementId=0x…. Structured inputs can use a JSON inputs fragment; numeric ABI inputs must be decimal strings rather than JSON numbers.

The account query selects read context; a connected wallet supplies actual signing identity and must match the selected chain. Resource-origin and unsigned-manifest policy are viewer configuration, not extra URL parameters. URLs and fragments are visible: do not put secrets in them.
