Hand over ownership or authorize a workshop ​

These are different transactions. A handover changes the NFT owner. A workshop grant permits selected registry updates without transferring the token.

Transfer the NFT

  1. Connect the current owner wallet and look up the exact component serial. Check the loaded collection, token ID and owner. Editing the search box alone does not change the loaded component.
  2. Enter the intended recipient and choose Transfer NFT. Review the direct three-argument safeTransferFrom call on the loaded collection, including sender and recipient.
  3. Authorize the transaction. After a successful receipt, refresh and confirm the new owner. A contract recipient must accept the ERC-721 safe transfer; a rejection reverts the ownership change.

The operation collects no payment and checks no physical handover. Coordinate those separately. Manager pause does not stop token transfers; collection pause does. Taking a component out of service does not by itself prevent transfer.

Grant temporary workshop access

As the current owner, enter the workshop address and choose a duration within the displayed maximum. Select Inspect workshop and preview expiry. Check the address, current grant and proposed chain-time expiry before choosing a permission preset.

Presets allow metadata updates, reporting a component missing, resolving a report, or all three. Each preset replaces that workshop's existing capabilities and expiry. Choosing another single permission does not add it to the first. A grant never permits NFT transfer or service-state changes.

After its receipt, the workshop connects its own wallet and looks up the same component. The contract enforces the capability and expiry at execution. At the expiry timestamp, the grant is already inactive; the displayed preview is not a guarantee that a delayed transaction will succeed.

Revoke or change a grant

Inspect the workshop and choose Revoke workshop access, or submit a new complete preset/expiry. Only the current token owner can manage the grant. Registry pause can block these writes; check the current state before relying on a planned revocation.

Every successful change of token owner permanently invalidates earlier grants, including when the token later returns to the grantor. A self-transfer preserves them; a failed transfer changes neither ownership nor the grant generation. The new owner must explicitly authorize any continuing workshop work.

Service state is not ownership or a missing report

Only the owner can choose Take out of service or Reactivate. These actions do not open, resolve or erase a missing report. The current contract permits metadata corrections and ordinary transfers in either service state.

Older deployments with irreversible Retired records retain that policy. Updating viewer files does not add reactivation or expiring-grant semantics to old contracts. Check compatibility with the deployment guide.
