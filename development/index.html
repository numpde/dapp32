Set up a source checkout

Use a non-root account with Git, Bash, Make, Docker and Compose. The workflows select a local Linux Docker engine; do not substitute a remote context for a server login.

Install the locked dependencies

git clone https://github.com/numpde/dapp32.git
cd dapp32
docker context ls
make dapps/deps/install DOCKER_CONTEXT=your-local-context
make js/deps/install DOCKER_CONTEXT=your-local-context
make ci DOCKER_CONTEXT=your-local-context

Replace your-local-context with the engine you intend to use. Omit the argument only when you want the interactive chooser. Noninteractive commands need the context on the Make command line. Each operation resolves that engine once and uses the same endpoint for child operations and cleanup.

Dependency installation is explicitly networked. The offline checks do not install missing dependencies for you. For the standalone viewer, only JavaScript dependencies are needed; its build guide also acquires its pinned base images explicitly.

Add your context to source Make commands. Run make help for prerequisites and current target options. README-only CI uses its lightweight length check, not application integration.

Host prerequisites and private files

Isolated Compose services disable Multipath TCP, so the kernel must expose the per-network-namespace net.mptcp.enabled setting. Host-network browser tools instead share the host's settings.

Release tools also need host Python 3.11+ and the maintained identity probe. Follow private-file qualification before using an operator instance on a different engine. Do not repair access failures by loosening the instance's permissions or changing its owner.

Source and documentation ownership

main owns implementation, fixtures and protocol-reference sources. gh-pages owns these task guides. Keep versioned protocol copies byte-identical to their source; current readers use CAM 1.4.0 / UI 1.1.0. Historical specifications are not compatibility promises.

For a release or published example, record the reviewed source commit. Do not mix an older deployment's ABI and signing rules with today's guide. The archived proof of concept is historical, not the starting point for current work.
